# 初回実装（v2.0.0）での自己判断事項

`要求.md` から読み取れない部分や曖昧な部分について、実装者（AI）が判断した内容を記録します。
どれも後から修正しても影響が小さいと判断し、質問で止めずに先に実装しました。
変更したい項目があれば、「他の選択肢」の記号（例: 3-B）か希望内容を指示してください。

## 1. 画面・表示

### 1-1. アプリ名
- ★A. `Itemization`（リポジトリ名から）
- B. 別名を指定してもらう
- 変更箇所: `javascripts/config.js` の `appName`、`index.html` の `<title>`

### 1-2. タブの新規作成方法
要求にはタブを作成できる旨のみで、操作方法の記載がありませんでした。
- ★A. タブ列の右に `+` ボタンを置く。新規タブは末尾に追加され、自動でアクティブになり、ルートアイテムが文字入力状態になる
- B. アクティブタブの直後に追加する
- C. ファイルメニュー等に「新規タブ」を置く（A と併用も可）

### 1-3. 最後の 1 個のタブの × ボタン
「最低 1 個は必ず表示」との兼ね合い。
- ★A. 削除でき、直後に空の新規タブを自動作成する（削除と新規作成は 1 回の Undo で戻る）
- B. タブが 1 個の時は × を非表示/無効にする

### 1-4. 「設定で変更可能な最大横幅」
設定画面の仕様が無いため、設定 UI は作っていません。
- ★A. 定数 `maxContentWidth = 360px`（文字領域の幅。枠と余白を除く）として `config.js` に置く
- B. 表示メニューなどに設定項目を設ける（設定値を文書 JSON に含めるか、別保存かも要決定）

### 1-5. アイテムの寸法・フォント・色
- フォント: 14px、行の高さ 20px、等幅フォント（Consolas → Courier New → BIZ UDGothic → MS Gothic → Osaka-Mono → monospace の順）
- 内側余白: 左右 8px / 上下 5px、角丸半径 6px、文字未入力時の最小文字領域幅 24px
- 階層間の横間隔 48px、兄弟間の縦間隔 10px
- メインエリア背景は薄いグレー（#f7f8fa）、関係線はグレー
- いずれも `config.js` / `renderer.js` で変更可能

### 1-6. 親アイテムの縦位置
要求は「関係線は縦中央が同じ時のみ直線」のみで、親の縦位置の規則は未指定でした。
- ★A. 親の縦中央を「最初の子と最後の子の縦中央の中間」に合わせる（一般的なマインドマップ風。子が 1 つなら直線になる）
- B. 親を最初の子と上端揃えにする（アウトライン風。2 つ目以降の子への線は曲線）

### 1-7. 同じ階層の横位置の決め方
- ★A. 階層ごとに、その階層の可視アイテム中で最も広い幅を基準に次の階層の左端を決める（タブ内の全ツリーで共通）
- B. 部分木ごとに決める（ただし要求の「従兄弟も同じ横位置」に反する）

### 1-8. [+][-] アイコンの表示条件
- v2.0.3 でユーザー指示により確定: 子があるアイテムには、文字入力・選択状態に関係なく常に表示する（旧案 C）。表示位置は関係線から 5px 上（初回実装より 3px 上へ移動）
- 初回実装（v2.0.0〜v2.0.2）は「文字入力中のアイテム＋折り畳み中のアイテム」に表示していた

### 1-9. 折り畳み状態の保存と Undo
- ★A. 折り畳み状態は文書 JSON（`collapsed`）に保存し、Undo/Redo の対象にする（要求「JSON が変化する操作は全て Undo 対象」に従う）
- B. 折り畳み状態は表示状態として別保存し、Undo 対象外にする

### 1-10. アクティブタブ・スクロール位置
- ★A. アクティブタブは文書 JSON とは別キー（`itemization2.ui`）で localStorage に保存し、Undo 対象外。タブごとのスクロール位置はメモリ上のみ保持（再読み込みで先頭へ戻る）
- B. スクロール位置も保存する

### 1-11. ユーザーが付けたタブ名（v2.0.5）
- ★A. タブ名を一度変更すると、以後はルートアイテムの文字列に追従しない。12 文字の制限もかけずにそのまま表示する。自動のタブ名に戻す操作は無い（Undo でのみ戻せる）
- B. 0 文字で確定したら自動のタブ名に戻す（ただし要求では「0 文字はキャンセル扱い」のため不採用）
- C. 変更後のタブ名にも 12 文字の制限をかける
- 補足: 現在のタブ名から変更せずに確定した場合は何もしない（自動のタブ名のままにする）
- 補足: 保存データにタブの `name` を追加した（省略可能なため旧データはそのまま読める）。スキーマ変更はマイナー番号を上げる対象だが、マイナー番号はユーザーの指示がある時だけ上げるため、パッチ番号のみ上げた（v2.0.5）

### 1-12. ツリーを全て開く／閉じる（v2.0.14）
- 選択アイテムがある場合、選択アイテム自身も開く／閉じるの対象に含める（閉じると選択アイテムの子孫が全て隠れる。開くと選択アイテム以下が全て見える）
  - 他の案: 要求の文言どおり子孫だけを対象にし、選択アイテム自身の開閉状態は変えない
- 子の無いアイテムは対象外（後から子を追加した時に、いきなり閉じた状態にならないように）
- ショートカット（Ctrl+E / Ctrl+Shift+E）は他のショートカットと同様に文字入力中以外で有効。文字入力中にメニューから実行した場合は、入力を確定してから実行する

### 1-13. ファイルを開く・保存（v2.0.15）
- 保存はブラウザのダウンロード（`<a download>`）で行う。Chrome 等の File System Access API（`showSaveFilePicker`）を使えば常に OS の保存ダイアログを出せるが、要求の記述（ブラウザの設定によってはそのままダウンロード）に合わせてダウンロード方式にした
- 保存する JSON は内部データ形式の文書 `{ format: 1, tabs: [表示タブ] }` そのもの（タブ ID・アイテム ID・折り畳み状態・タブ名を含む）。開く時は ID を振り直す
- 1 つのファイルに複数のタブが含まれていれば、全てを末尾に追加する（このアプリが保存するファイルは常に 1 タブ）
- 開く形式は拡張子ではなく内容（`{` で始まれば JSON、`<` で始まれば SVG）で判定する
- SVG・PDF は画面と同じ折り畳み状態で描く（他の案: 全て展開して描く）。選択状態の青枠は描かない。[+][-] アイコンは v2.0.16 でユーザー指示により描かないことに確定
- SVG の文字は画面と同じ等幅フォント指定（閲覧環境のフォントで表示される）。PDF は IPAゴシックを埋め込む
- PDF は内容に合わせた 1 ページ（他の案: A4 等の定型サイズに分割・縮小）
- PDF ライブラリ: pdf-lib 1.17.1（MIT）＋ @pdf-lib/fontkit 1.1.1（MIT）。フォント: IPAゴシック Ver.003.03（IPAフォントライセンスv1.0）
  - IPA フォントの公式配布サイトにこの環境から接続できなかったため、Ubuntu の `fonts-ipafont-gothic`（上流の 00303 を無改変で収録）から取得した
  - ライセンス上、無改変での再配布とライセンス文の添付が条件。`file://` でも読み込めるよう gzip＋base64 の JS に格納したが、展開後のバイト列は元の `ipag.ttf` と同一（SHA-256 を `javascripts/vendor/README.md` に記載）。格納形式の変更であってフォントの改変ではないと判断した
  - PDF へのサブセット埋め込みはライセンス第2条5項（エンベッドされたフォント）で認められている
  - 他の案: フォントを同梱せず、PDF 作成時に利用者が `ipag.ttf` を選択する（リポジトリは軽くなるが操作が増える）

## 2. 文字入力

### 2-1. ルートで ENTER した時の子の位置
- ★A. 最後の子として追加
- B. 最初の子として追加

### 2-2. ENTER / SHIFT+. でアイテムを新設した時の選択状態
要求「元アイテムの選択状態は解除」について、
- ★A. 選択状態をすべて解除する
- B. 元アイテムだけ選択解除し、他の選択は残す

### 2-3. ENTER で新設した時の Undo 単位
- ★A. 「元アイテムの文字確定」と「アイテム新設」を別々の履歴にする（1 回目の Undo で空アイテムが消え、2 回目で文字が戻る）
- B. 1 つの履歴にまとめる

### 2-4. 上下キーで移動先の兄弟が無い時の探し方
要求は「親の兄の最後の子（下キーは親の弟の最初の子）」。
- ★A. 表示中のアイテムを文書順に辿り、同じ階層で直前（直後）のアイテムへ移動する。通常のケースでは要求と同じ結果になり、親の兄に子が無い場合はさらに前の同階層アイテムを探す
- B. 親の兄（弟）だけを調べ、子が無ければ移動しない

### 2-5. 「1 行目」「最終行」「行頭」「行番号」の行の定義
- ★A. 折り返しを含む表示上の行（見た目の行）で判定する
- B. 改行文字で区切った論理行で判定する

### 2-6. 折り畳まれた子への移動
- ★A. 折り畳み中の子は存在しないものとみなす（右キー・上下キーで移動しない）
- B. 右キーで自動的に展開して移動する

### 2-7. 0 文字アイテムを BackSpace で削除した後のフォーカス
要求に記載がありませんでした。
- ★A. 兄アイテムの末尾へ（兄が無ければ親の末尾へ）文字入力を移す
- B. 文字入力を終了する
- また、BackSpace に加えて Delete キーでも同じ動作にしています（要求「BackSpace キー等」より）

### 2-8. 空のまま文字入力を終えたアイテム
- ★A. そのまま空のアイテムとして残す
- B. 自動的に削除する

### 2-9. SHIFT+. で折り畳み中のアイテムに子を追加した場合
- ★A. 自動的に展開してから追加する（ドラッグで子としてドロップした場合も同様）

### 2-10. 編集メニューの「元に戻す」を文字入力中に選んだ場合
- ★A. 入力中の文字を確定してから、アプリの Undo を行う
- B. TEXTAREA の Undo を行う

### 2-11. 文字入力中に TEXTAREA の外（別ウィンドウ等）へフォーカスが移った場合
- ★A. ページ内の別要素（メニュー・タブ等）へ移った時は確定・終了。ウィンドウ切替では入力状態を維持

### 2-12. コピー・貼り付け（v2.0.6）
- コピーする範囲
  - ★A. 選択アイテムのみ。未選択の子孫は含めず、選択アイテムは「選択されている最も近い祖先」の子にする（要求「選択したアイテム間の親子関係を維持」の解釈）
  - B. 選択アイテム以下の部分木を丸ごとコピーする（ドラッグ移動と同じ扱い）
- 書き出す箇条書きの記号とインデント
  - ★A. `・` ＋ 階層ごとに 2 空白。複数行アイテムの 2 行目以降は記号の後ろに揃える
  - B. マークダウン形式（`- ` ＋ 2 空白）
  - 注: 2 行目以降が記号の文字で始まるアイテムは、貼り直すと別アイテムに分かれる（JSON 形式で貼り付ける場合は問題ない）
- 貼り付け後の選択状態
  - ★A. 変えない（続けて貼り付けると同じ親の子として追加される）
  - B. 貼り付けたアイテムを選択状態にする
- 貼り付け位置
  - ★A. 最後の子として追加
  - B. 最初の子として追加
- 「最後に選択したアイテム」: 選択に追加した順番の最後（クリック・CTRL+クリック・範囲選択の順）
- 箇条書きの記号に、要求の記号に加えて半角中黒 `･` と `•` も含めた
- `#` 見出しは、同じインデントの他の記号より浅い階層として扱う（マークダウンの「見出しの下の箇条書き」を子にするため）
- 記号なしのアイテムの中の空行は改行として扱う（アイテムの区切りにはしない）
- 罫線ツリー・番号付きの解釈（v2.0.7）
  - 罫線ツリーの階層は、分岐記号（├ └ など）の左側の幅（縦線・空白）で決める。縦線は 1、全角空白は 2 として数える
  - ASCII の罫線（`|-- ` `` `-- `` `+--`）や太線（┣ ┗ ┃）、二重線（╠ ╚ ║）にも対応した
  - 番号は文字列から取り除く（記号と同じ扱い）。`1.2` などの区切り付き番号は区切りの数で階層を決める
  - v2.0.8 でユーザー指示により、番号の末尾に . が無い場合は空白必須に変更（「1.5倍」は番号付きにならない）。「2024 年」のように数字＋空白で始まる行は引き続き番号付きと解釈される
  - v2.0.9: ユーザー指示の ①〜⑨ に加えて ⑩〜⑳ も記号として扱う（10 項目以上のリストのため）
  - v2.0.9: `1-1-1` の区切り `-` は `.` と混在してもよい（`1.2-3` も 3 階層）。「2024-10-10 打合せ」のような日付で始まる行も 3 階層の番号付きと解釈される
  - v2.0.9: `(1)` や ①〜⑳ はインデントが同じなら `1.` や `・` と同じ階層（兄弟）として扱う。「1. ＞ (1) ＞ ①」のように種類で階層を決める案もある
  - v2.0.10: 英字 1 文字の番号に対応。ただし英字 1 文字だけで末尾に `.` が無く空白が続く行（`A 項目`、`I think so`）は、英文の行頭と区別できないため番号付きにしない
    - 他の案: 数字と同様に番号付きとして扱う（「I think so」は「think so」になる）
  - v2.0.10: `e.g. this`、`U.S. policy` のような略語で始まる行は、`D.e.` と同じ形のため番号付き（「this」「policy」）と解釈される
  - 罫線ツリーの枝の後ろに番号や記号がある場合（`├ 1. 設計`）は、番号・記号を文字列に残す
- CSV/TSV の解釈（v2.0.11）
  - 空のセルは飛ばして次の列をその子にする（他の案: 空のアイテムとして残す / 空のセルを「上の行と同じ」とみなして結合する）
  - 1 列目などが同じ値の行も結合せず、行ごとに別のアイテムにする（他の案: 同じ値の親を共有するツリーにまとめる）
  - 空行は無視する（行数・列数の判定に含めない）
  - TSV と CSV の両方の条件を満たす場合は TSV を優先する
  - `"` で囲まれた値の中の空白・改行はそのまま残す（例の「I⏎JK」は改行付きの 1 アイテム）
  - 「Hello, world」のように , を含む文が 2 行以上で列数が揃うと CSV と解釈される
- 形式を指定したコピー（v2.0.12）
  - 番号付き: 桁揃えは番号の後ろを空白で埋める方式（`1.  A` / `10. J`）。番号を右揃えにする方式（` 1. A` / `10. J`）は、貼り直した時にインデント量が変わって階層がずれるため不採用
  - 番号付き: 子のインデントは親の文字列の開始位置に合わせる（他の案: 階層ごとに固定幅）
  - マークダウン: 複数行のアイテムの改行は行末の 2 空白で表す（他の案: `<br>` を使う）。マークダウンの特殊文字はエスケープしない
  - CSV/TSV: 経路ごとに 1 行とし、共通の親も各行に繰り返す（他の案: 親は最初の行だけに書き、以降の行は空欄にする表形式。ただし現在の貼り付けでは空欄を飛ばすため、貼り直すと階層が崩れる）
  - ツリー（v2.0.13）: 最上位のアイテムが複数ある場合は、それらも枝（├── / └──）で表す。tree コマンドのように枝なしの行を複数並べると、2 つ目以降の最上位アイテムが直前のアイテムの続きの行と区別できず、貼り直した時に階層が崩れるため（他の案: 先頭に「.」の行を置いてその子として並べる）
  - いずれもクリップボードには文字列だけを書き込む（Itemization に貼り直した時も、その形式の文字列として解釈される）
- メニューの「貼り付け」はクリップボード読み取り API を使うため、`file://` ではブラウザが許可しない。その場合はアプリ内の擬似クリップボードのみ貼り付けられる（CTRL+V は制約なし）

## 3. 選択・ドラッグ

### 3-1. 枠線クリックの判定幅
- 枠線とその両側 ±3px を「枠」とみなす（v2.0.2 でユーザー指示により確定。`config.js` の `borderHitWidth`）。初回実装は外側 2px 〜 内側 3px だった

### 3-2. アイテム以外の領域をクリックした時
- ★A. （ドラッグせずに離した場合）選択をすべて解除する
- B. 選択を維持する

### 3-3. アイテムをクリックした時の既存の選択
- ★A. 修飾キー無しのクリックは、他の選択を解除してそのアイテムのみ選択する

### 3-4. ドロップ位置の決め方
- ★A. ドロップ先アイテムの上部 3 割＝その直前の兄弟、下部 3 割＝直後の兄弟、中央＝最後の子。ルートの上では常に子。アイテム以外の場所でドロップした場合は移動しない。ドロップ位置は青線（兄弟）/ 点線枠（子）で表示
- B. 中央＝最初の子にする
- C. アイテムの右側の空白へのドロップも子として扱う

### 3-5. 未選択のアイテムをドラッグした場合
- ★A. 既存の選択を解除し、そのアイテムのみを選択してドラッグする
- B. 既存の選択に追加してまとめてドラッグする

### 3-6. ドラッグ・範囲選択中に画面端へ近づいた場合
- ★A. 自動スクロールする

### 3-7. ルートアイテムの選択
- ★A. 選択はできるが、ドラッグ移動・削除の対象からは除外する

## 4. Undo/Redo・保存

ショートカットは「今後指示」とのことですが、Undo/Redo が使えないと不便なため最小限だけ実装しました。
- ★A. 文字入力中以外: `Ctrl+Z`（Mac は ⌘+Z）= 元に戻す、`Ctrl+Shift+Z` / `Ctrl+Y` = やり直す
- 文字入力中は TEXTAREA 本来の Undo/Redo（要求どおり）
- v2.0.17 で文字の装飾を追加した際、入力中の Undo/Redo をアプリ独自（アイテム内の文字・装飾の変更を 1 操作ずつ）に変更（6-6 参照）

### 4-2. 履歴の保持
- ★A. 最大 500 件、メモリ上のみ（再読み込みで履歴は消える）
- B. 履歴も localStorage に保存する

### 4-3. 保存のタイミング

## 6. 文字の装飾（v2.0.17）

### 6-1. WYSIWYG の実現方法
TEXTAREA は文字ごとにフォントサイズや色を変えられないため。
- ★A. 見えない TEXTAREA でキー入力・IME・クリップボードを受け、装飾付きの文字・選択範囲・カーソルを CANVAS に描く（表示と SVG/PDF 出力が完全に一致する）
- B. contenteditable の DIV で編集する（ブラウザごとの挙動差や、CANVAS 描画との寸法のずれが出やすい）

### 6-2. 選択が無い時の文字単位の装飾ボタン
要求「選択中の文字列にだけ適用可能」に従った。
- ★A. 無効表示にして押せないようにする
- B. 押すと次に入力する文字に適用する（ワープロ風）

### 6-3. 入力した文字の装飾
- ★A. 置き換えた文字（無ければ直前の文字、先頭なら直後の文字）の装飾を引き継ぐ（ワープロ風）
- B. 常に装飾なしで入力する

### 6-4. 色の選択肢
- ★文字色: 黒・灰・茶・赤・橙・黄・黄緑・緑・青緑・水色・青・紺・紫・赤紫・桃・オリーブの 16 色。白地で読めるよう黄は少し暗くした。白は文字色として読めないため入れずにオリーブにした
- ★背景色: 上記を白と 8:2 で混ぜた薄い色（同じ色の文字と背景を選んでも同化しない）
- 各一覧に「標準の色（黒）」「色なし」を設けて解除できるようにした
- 変更箇所: `config.js` の `colorNames` / `paleRatio`

### 6-5. フォントサイズの選択肢と行の高さ
- ★10 / 12 / 14（標準）/ 18 / 24 / 32px。行の高さはその行の最大サイズに比例（14px → 20px）
- 変更箇所: `config.js` の `fontSizes`

### 6-6. 文字入力中の Undo/Redo
TEXTAREA 本来の Undo では装飾の変更を戻せないため。
- ★A. アイテム内の文字入力・装飾の変更をアプリ独自に 1 操作ずつ戻す（連続入力はまとめる）。確定後はアプリの履歴で 1 件
- B. 装飾の変更のたびに入力を確定してアプリの履歴に積む

### 6-7. ツールバーの位置
- ★A. 入力中のアイテムの上（スクロールで上が隠れる場合は下）に重ねて表示し、アイテムと一緒にスクロールする
- B. 画面上部に固定表示する

### 6-8. 装飾のコピー
- ★A. アイテムのコピー（JSON 形式）には装飾を含め、文字列形式には含めない。入力中の文字列のコピー（TEXTAREA）は文字列のみ

### 6-9. 「装飾を消す」の対象（v2.1.2）
「ツールバーで操作可能な全ての文字装飾」とのことなので、アイテム背景色・寄せ方もツールバーの装飾に含めた。
- ★A. 文字の装飾に加え、アイテム背景色・寄せ方（左寄せに戻す）も消す
- B. 文字単位の装飾（フォントサイズ〜文字背景色）だけを消す

### 6-10. アイテム選択中のツールバー（v2.1.2）
- ★複数選択時は、ボタンの操作を選択中のすべてのアイテム（アクティブタブ内）に適用する。表示位置は最後に選択したアイテム
- ★ツールバーはアイテムに重ねて表示するため、隣のアイテムを隠すことがある（ドラッグ・範囲選択中は隠す）

## 7. タブの設定（v2.1.5）

### 7-1. ステータスの色
- ★背景色と文字色の組で 16 色（灰・黒・赤・橙・黄・黄緑・緑・青緑・水色・青・紺・紫・桃・茶・深緑・深紅）。明るい色は黒文字、濃い色（黒・紺・茶・深緑・深紅）は白文字
- 保存データには色の値ではなくキー（'gray' など）を記録する（色味を後から調整できるように）
- 変更箇所: `config.js` の `statusColors`

### 7-2. 最大表示幅のスライダー
- ★10px 刻み。現在値を右に表示

### 7-3. ステータス名の検証
- ★前後の空白を除いて 1〜12 文字。不正な行があれば OK で閉じずに赤枠とメッセージを表示

### 7-4. 設定の変更と Undo
- ★OK での設定変更は文書の変更として 1 回の Undo で戻る
- 設定の無い既存データ・ファイルは初期値で補う

## 8. ステータスの表示（v2.1.6）

### 8-1. アイテムに記録する値
- ★ステータス名を記録する。タブの設定で名前を変えた時は、そのタブのアイテムの名前も書き換える（削除後に同じ名前を登録すると色が戻る要求を満たすため、ID ではなく名前で結び付けた）

### 8-2. バッジの見た目
- ★角丸（両端が丸い）のラベル。8px の太字、高さ 12px、左右の余白 5px。文字列との間隔 3px

### 8-3. サブメニューの表示
- ★ステータス名をタブの設定の色のバッジで表示する。登録が 0 個なら「（ステータスが登録されていません）」を無効表示

### 8-4. コピー・貼り付け
- ★アイテムのコピー（JSON 形式）ではステータスも貼り付ける。貼り付け先のタブに無いステータス名は削除されたステータスの表示になる
